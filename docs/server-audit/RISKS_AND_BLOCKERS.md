## 3. 共享架构中的安全约束

共享入口、语音或 Registry 不得扩大花盆执行权限。保留唯一 operating_mode 四态、activity/fault_codes 分工、确定性云决策、独立 Worker/jobs、原子 POST claim、设备 token 归属与轮换、额度预扣及恢复对账。

语音识别/LLM 给出的文本是不可信输入；家庭经验必须用户确认，策略必须有来源与版本；执行参数由花盆确定性服务生成，Pi 再校验。若未来共享平台要求直接用 LLM JSON 操作泵，应拒绝该接口设计，而非在 Pi 复制另一套完整决策来补救。

物理安全也不随云端平台化变化：正确液位差、开放空气间隙、固定喷嘴、滴漏验证、10kΩ 下拉、P451、标定和紧急关泵仍是前提；GPIO 回读不是电机电流证明。

- 未连接树莓派、麦克风、摄像头、水泵；没有任何物理验收通过声明。
- 未验证全部潜在远程系统；“本机未发现数据库/云 ASR”只限定在审计范围内。

因此业务测试总数 0，通过 0、失败 0；Mock 0、真实 Provider 请求 0、物理测试 0。源码/运行证据足以提出共存建议，尚不足以签发生产部署或硬件安全验收。

## 5. 回滚与下一步边界

本轮没有业务/部署变更，不需要生产回滚。新增八份报告可以按普通文档版本管理撤回；没有删除任何原文件。

未来 flower 发布应保存镜像摘要、Compose、迁移版本、Nginx 独立站点和数据库/uploads 备份。回滚限定 flower 范围：先停止新命令并确认设备安全保持，再恢复兼容镜像/配置；数据库不兼容时才按已演练流程恢复独立库，不能盲目 Alembic downgrade。宿主机 Nginx 配置恢复及 reload 应在单独变更窗口验证，不能牵连 City Front 或既有 aibot。

若安装 Docker 导致 VPN/转发回归，应恢复事先记录的主机网络状态，不能简单 flush 防火墙。具体回滚命令需在已确定 Docker 版本和实际部署清单后编制，本轮不提供可误运行的全局清理命令。
